# 교훈 사례집 — 제가 한 실수와 막는 방법

이 문서는 **AI(저)가 이 저장소에서 실제로 한 실수**를 모아둔 것입니다.

같은 실수를 두 번 하지 않으려고 적습니다.
새 작업을 시작할 때 이 문서를 먼저 읽으면, 같은 함정에 안 빠집니다.

사례마다 이렇게 적습니다.

- **무슨 일이 있었나** — 실제로 일어난 일
- **왜 그랬나** — 원인
- **어떻게 막나** — 다음부터 지킬 것

---

## 🚨 1급 — 주인에게 직접 손해가 간 실수

### 사례 1. 푸시만 하고 `main` 에 안 합쳐서, 주인이 기능을 못 찾았다

**무슨 일이 있었나**
새 기능 3개를 만들어 작업 브랜치에 올리고 "배포했습니다" 라고 말했습니다.
주인은 앱에서 그 기능을 찾지 못했습니다.

**왜 그랬나**
운영에 나가는 브랜치는 `main` 하나뿐인데,
작업 브랜치에 푸시하면 Vercel은 연습용(Preview)만 만듭니다.
저는 "푸시 = 배포" 라고 착각했습니다.

**어떻게 막나**
```
❌ 수정 → 커밋 → 푸시 → "다 됐습니다"
✅ 수정 → 커밋 → 푸시 → PR → main 병합 → "다 됐습니다"
```
→ `CLAUDE.md` 의 **1순위 규칙**으로 올렸습니다.
→ 병합 후 1~2분 기다려야 앱에 나온다는 것도 함께 알립니다.

### 사례 2. 헬로톡 글이 2000자를 넘어서 올라가지 않을 글을 드렸다

**무슨 일이 있었나**
곤피라(24편-2) 헬로톡 글을 드렸는데 **2057자**였습니다.
헬로톡 한도는 2000자입니다. 주인이 올리려다 막혔을 수 있습니다.

**왜 그랬나**
눈대중으로 길이를 맞췄습니다. 한 번도 세어보지 않았습니다.

**어떻게 막나**
매 편마다 **글자수를 세어서 숫자로 알려드립니다.**

| 기준 | 글자수 |
|---|---|
| 안전 | 1800자 이하 |
| 위험 | 1950자 넘음 → 줄인다 |

줄일 때는 **영어부터** (영어가 약 950자로 가장 깁니다).
→ `글쓰기-규칙.md` **규칙 9**로 등록했습니다.

### 사례 3. 검색이 안 되는 블로그 제목을 24편이나 드렸다

**무슨 일이 있었나**
주인이 "블로그로 벌어와" 라고 했을 때 제목을 다시 봤습니다.
24편 전부 **사람들이 검색하지 않는 제목**이었습니다.
글은 좋았는데 아무도 찾아올 수 없는 제목이었습니다.

**왜 그랬나**
글의 분위기를 살리는 제목을 썼습니다.
읽는 사람이 **어떤 말로 검색하는지**를 생각하지 않았습니다.

**어떻게 막나**
제목 규칙을 바꿨습니다.

1. **온천 이름을 맨 앞에** (사람들은 이름으로 검색합니다)
2. `|` 뒤에 두 번째 검색어
3. 25~35자

예) `아키우 온천 센다이에서 가는법 | 차로 30분 온천 마을 정리`
→ 24편 전부 다시 썼습니다.

## 📖 2급 — 글의 신뢰를 깨뜨리는 실수

### 사례 4. 안 가본 곳을 가본 것처럼 썼다

**무슨 일이 있었나**
14편(안 가본 곳)에 **"저는 이게 제일 좋아요"** 라고 썼습니다.
주인이 바로 잡아냈습니다. *"못가본곳인데 이런 문구가"*

**왜 그랬나**
글을 생생하게 쓰려다 보니 경험한 말투가 섞였습니다.

**어떻게 막나**
안 가본 곳(📖)에서는 **들은 말투**만 씁니다.

| 안 가본 곳에서 ❌ | 이렇게 ✅ |
|---|---|
| ~였어요 / ~했어요 | ~라고 합니다 / ~라고 해요 |
| 저는 이게 제일 좋아요 | 저는 이런 걸 좋아해서 끌려요 |
| 추천합니다 | 가보고 싶습니다 |

→ `글쓰기-규칙.md` **규칙 7**로 등록했습니다.
→ **이게 이 블로그와 책의 가장 중요한 약속입니다.**

### 사례 5. 공동 순위를 빠뜨렸다 (24위 곤피라)

**무슨 일이 있었나**
42편까지 쓰고 나서 표를 세어보다가,
**공동 24위 곤피라 온천향(가가와)이 빠진 것**을 발견했습니다.
24위가 두 곳인데 가미스와만 쓰고 넘어갔습니다.
게다가 이곳은 69위→24위로 **이번에 가장 많이 오른 곳**이었습니다.

**왜 그랬나**
"24편을 썼으니 24위는 끝" 이라고 생각했습니다.
공동 순위가 있다는 걸 매번 확인하지 않았습니다.

**어떻게 막나**
새 편을 쓸 때마다 **그 순위가 공동인지 먼저 확인**합니다.

```bash
# 공동 순위(두 번 나오는 번호) 찾기
grep -oE "^\| \*{0,2}[0-9]+" docs/온천100선-순위표.md \
  | grep -oE "[0-9]+" | sort -n | uniq -d
```

지금까지 확인된 공동 순위: **19 · 24 · 26 · 32 · 38 · 42**

나중에 주인이 자료를 주셔서 그 자료로 썼습니다.

**왜 그랬나 (왜 거절했나)**
여기서 지어내면 **앞의 서른 편까지 믿을 수 없는 책**이 됩니다.
한 번 거짓이 섞이면 전체가 무너집니다.

**어떻게 막나**
모르면 **모른다고 말하고 멈춥니다.**
주인의 자료를 기다리는 편이 낫습니다.
→ 이건 실수가 아니라 **잘한 사례**로 남깁니다.

### 사례 7. 책에 사실과 다른 내용이 들어갔다

**무슨 일이 있었나**

**왜 그랬나**

추측은 추측이라 틀렸습니다.

**어떻게 막나**

## 🔍 4급 — 상황을 잘못 본 실수

### 사례 12. 저장소가 다른 앱으로 바뀐 줄 알고 잘못 보고했다

**무슨 일이 있었나**
저장소가 안드로이드 앱으로 바뀌었다고 보고했습니다.
**사실이 아니었습니다.** 컨테이너가 다른 브랜치를 보고 있었을 뿐이고,
`origin/main` 에는 전부 그대로 있었습니다.

**왜 그랬나**
지금 보고 있는 브랜치를 확인하지 않고 결론을 냈습니다.

**어떻게 막나**
"없어졌다 / 바뀌었다" 고 말하기 전에 꼭 확인합니다.

```bash
git branch -a          # 지금 어느 브랜치인지
git log origin/main -3 # main 에는 뭐가 있는지
```

그리고 잘못 봤으면 **바로 솔직하게 정정**합니다.
주인을 놀라게 한 건 실수보다 더 미안한 일입니다.

### 사례 13. 글꼴에 없는 기호를 써서 두부(□)로 나왔다

**무슨 일이 있었나**
- 카드에 `✓` `☑` 를 썼는데 **□** 로 나왔습니다
- 한자 `鶴の湯` 를 썼는데 **□□□** 로 나왔습니다

**왜 그랬나**
글꼴에 그 글자가 없으면 네모(두부)로 나옵니다.
저는 글꼴에 그 글자가 있는지 확인하지 않았습니다.

**어떻게 막나**
- 처음 쓰는 기호는 **미리 그려서 눈으로 확인**합니다
- 없으면 있는 것으로 바꿉니다 (`✓` → `●`)
- 체크박스 같은 건 **도형으로 직접 그립니다**
- 한자가 섞이면 한자 되는 글꼴을 씁니다

### 사례 16. 주인에게 자꾸 "확인해 주세요" 라고 부탁했다

**무슨 일이 있었나**
주인이 말씀하셨습니다. **"알려달라고 하지말고 사이트등 조사해서 글 쓰기"**

제가 이런 걸 자꾸 여쭤봤습니다.
- 네이버 블로그에 '메일로 글쓰기' 기능이 있는지
- 부산에서 어디로 직항이 있는지
- 앱 비밀번호가 뭐였는지

**왜 그랬나**
조사를 할 수 없어서입니다. 2026-11에 다시 시험해 봤습니다.

| 주소 | 결과 |
|---|---|
| 네이버 · 네이버 개발자센터 | 막힘 |
| 위키백과 (일본어·영어) | 호스트 이름도 못 찾음 |
| 구글 | 막힘 |
| 항공사·항공노선 사이트 | 호스트 이름도 못 찾음 |

바깥 인터넷이 **전부** 막혀 있습니다. 네이버만이 아닙니다.
네트워크를 열어달라고 요청도 해봤지만 거부됐습니다.

**어떻게 막나 — 부탁을 줄이는 세 가지 방법**

1. **모르면 그 대목을 빼고 쓴다.**
   빈칸을 주인에게 채워달라고 하지 말고, 아예 안 쓰는 쪽을 먼저 고릅니다.
   50편 하하가하타가 그랬습니다. 아는 게 적어서 짧게 쓰고,
   대신 제가 직접 셀 수 있는 '절반 결산'으로 채웠습니다.

2. **제가 셀 수 있는 것으로 채운다.**
   순위표는 저장소에 있습니다. 세는 건 인터넷 없이도 됩니다.
   - 몇 칸 올랐나 / 내렸나
   - 지역별로 몇 곳인가, 다녀온 곳은 몇 곳인가
   - 공동 순위가 어디인가
   - 가장 많이 오른 곳, 가장 오래된 곳
   → 51·53편의 좋은 대목은 전부 '세어보니' 에서 나왔습니다.
